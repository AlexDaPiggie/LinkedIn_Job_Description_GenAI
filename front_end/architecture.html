How it works

A small, deliberate pipeline: collect facts, ask the model for structured JSON, validate it, check it with plain rules, then render it. The AI never writes pay numbers, and every edit is saved so you can undo it.

Generation pipeline

  1. IntakeGuided questions, or upload an old JD to auto-fill.
  2. GenerateFixed instructions first, your data last, wrapped as data not commands.
  3. ValidateJSON checked against a schema. One automatic retry if malformed.
  4. LintFree rule checks: bias words, pay range, bullets, reading level.
  5. RenderLinkedIn-ready Markdown, Word export or copy-paste.

What is free and what costs credits

  • Free, no account: generate, upload and auto-fill, quality check, quick edits, section rewrites, undo, copy, Word export, screening questions.
  • 1 credit: a refine request you type yourself. New accounts get 20 free credits. If the AI call fails, the credit is refunded automatically.

Design choices

  • Structured output. Pydantic schemas define the draft. Truncated or invalid output is retried once, then reported as an error.
  • Pay is never AI-written. Your numbers are formatted by code and attached after generation, so the model cannot invent or change them.
  • Rule-based linter. Gender-coded words (Gaucher et al., 2011), age-coded phrases, filler, duplicates, bullet caps, pay checks by location, reading grade. No extra AI calls, so it costs nothing.
  • Assumption flags. Requirements that share no words with your answers are marked "verify".
  • Untrusted uploads. File text is cleaned, capped, wrapped in delimiters, and the extracted fields are filtered to known names and types.
  • Prompt caching friendly. Static instructions come first. Identical requests are answered from an in-memory cache without calling the model.

Money and safety

  • Atomic credit ledger. One database function checks and subtracts credits in a single step. Each charge has a unique key, so a repeated request never charges twice.
  • Stripe. The server decides price and credits from a fixed pack list. Webhooks are verified, credited once per Checkout Session, and failed attempts are retried by Stripe.
  • Free endpoint protection. Cloudflare Turnstile, a per-IP daily limit that reads the client address only from trusted proxy hops, and a global daily call cap as a kill switch.
  • Signup abuse. Email must be confirmed first. One free grant per real mailbox (Gmail dots and plus tags collapsed). Throwaway email domains are blocked.

Stack

Vanilla JavaScript front end, FastAPI back end, Supabase for auth and data, Stripe Checkout for payments, OpenRouter for model access, hosted on Hugging Face Spaces. The quality linter in src/quality has no dependencies on the rest of the app and can be reused on its own. See the evaluation results for how models compare.

The pay-range summary by location is a screening aid, not legal advice.
